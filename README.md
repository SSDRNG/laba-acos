Скрипт log_archiver.sh следит за заполнением папки /log.
Если папка занята на более чем N%, он архивирует M старых файлов в tar.gz, 
кладет архив в /backup и удаляет заархивированные файлы из /log, чтобы освободить место

Как ограничивалась папка /log 
sudo mkdir -p /log                      
truncate -s 100M ~/log.img              
sudo mkfs.ext4 -q ~/log.img           
sudo mount -o loop ~/log.img /log       
sudo chown $USER /log                    
sudo mkdir -p /backup                   

Для запуска 
sudo ./log_monitor.sh /log N M
также можно сменить папку для архивов (по умолчанию стоит /backup)
BACKUP_DIR=~/backup ./log_monitor.sh /log N M 

расшифровка кодов завершения:
0 - все ок
1 - передано не 3 арг
2 - не прошла проверка N 
3 - не прошла проверка М
4 - папка не существует/ нет прав на чтение
5 - папка не ограничена
6 - папка /backup находится внутри /log
7 - не получилось узнать % заполнения
8 - не получилось создать /backup
9 - не получилось создать архив
